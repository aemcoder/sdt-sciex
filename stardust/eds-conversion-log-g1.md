## 3. Reuse decisions (hero-small · icon-card · tabs)

- **Ported `blocks/hero-small/` (sciex.com EDS port, contact-us) — NOT reused → `hero-band`.** Its `extractBlockData()` reads a 16-cell positional shape (`clonedCells[1]` heading … `[15]` media, buttons at 3/6/9) and value-slots text (`innerText.trim()` → uneditable in Experience Workspace, 
  `/* eslint-disable */` port kept verbatim). A one-cell picture row would land in that positional reader and render nothing; adding the v3 composition would mean branching the ported `decorate`, not appending a variant rule. The v3 `.hero-small` is a different pattern (picture band with scrim / product band), so it gets its own block; `hero-band` is the brief's fallback name.
- **Ported `blocks/icon-card/` — NOT reused → `cards icon-grid`.** Its shape is 7 config rows (id, heading, font type, heading type, description, columns, card type) + 7-cell card rows (D10 violation, D14 display copy as config, value-slotting); the v3 icon cards are a plain repeating grid = the `cards` content model (D9/D11), so they ride the site's canonical `cards` block as a variant. Class names avoid the ported block's `.icon-card` selectors (`.icongrid-*`).
- **Existing `tabs` (home portfolio) — NOT extended → `section-tabs`.** The home model is label \| content with prose/picture per panel; the software panels hold whole components (card grids, an accordion whose items hold card grids) — nesting blocks in a cell is D2. The brief's preference for a `tabs vertical` variant applied only "if the content model matches"; it does not, so the block that adopts sibling sections is separate (and the home `tabs.js` stays untouched).
- **`columns` preferred over a new `split` block** (brief's preference): the media \| content row IS the Block Collection columns model; stock JS suffices, variant CSS carries the split geometry.
- **`cards image-text` preferred over a new `image-text` block** (brief: "check Block Collection `cards` fit first"): thumb + title + text + link per row is the cards model.

## 5. Decisions / justifications

- **Heading LEVEL encodes the live type scale** (h2 = text-charlie, h3 = text-delta, h4 = text-echo) in `lead`, `columns lead`, every card/imgtext/icon-grid/section-tabs head. Live authors picked these sizes per instance (`h2.text-delta`, `h3.text-echo` both exist); a DA author picks H2/H3/H4 from the dropdown and gets the same three sizes — no style pickers, no per-instance modifiers. Trade: the outline can jump (h1 → h3 on CE/HPLC, h1 → h4 on technology) exactly where the live outline does; the lint has no level check and the round-trip classifier treats every level as `heading` (no ROLE SWAP).
- **Card titles `<h3>`** (live `div.card__title` / `p.imgtext__title`): the accepted ENCODE canonicalisation (`main h3` = text-lg-bolder, identical paint). The round-trip gate runs against byte-identical fixtures whose ONLY change is that tag (`stardust/.work/deploy/g1/proto-canon/`, served through the dev server; `h3.card__title { font: inherit }` reset) — same technique as the pharma log.
- **Spacer dropped** (1 px inert div; § 1). **Live `<style>` injection → block CSS** (D15).
- **Media**: one rendition per image — the widest ≤ 1920 (`-w1920.jpg` where the prototype used a `<picture>`, else the single original), never srcset; authored as `https://content.da.live/aemcoder/sdt-sciex/media/products/<file>`; 87 files (81 raster + 6 icon SVGs, 12.5 MB) listed in `stardust/.work/deploy/g1/uploads.json` / `ready.json`. Alt text `""` everywhere (live). Icon SVGs extracted from the live inline markup (`stardust/.work/deploy/g1/media/icon-*.svg`, pure vector, stroke #141414).
- **Links**: root-relative for the migration set (`/`, `/applications/pharma-and-biopharma`, the KB article, `/events`, `/resource-hub`, `/resource-hub/regulatory-documents`, `/about-us/contact-us`, the 8 G1 pages); every other sciex.com path → `https://sciex.com/<path>` (query strings kept); other hosts verbatim; `target="_blank"` kept where live has it (pharma precedent).
- **`<br>` inside a paragraph kept** (software "Analyst software": a deliberate double line break in the live copy — editorial, not layout).
- **Consumables Description**: live page has no meta description → the hero lede's first sentence (165 chars).
- **Tab / accordion adoption keys**: section-metadata `tab` / `accordion` values are matched to the block rows on normalised text (case/whitespace-insensitive). Authors type the label twice (row + metadata); an unmatched section is left in place, visible.
- **Bare-text richtext**: the CE three-card bodies carry copy with no `<p>` (`<div class="card__text">text</div>`) — the generator's first cut dropped them (round-trip 🟡 MISSING BODY ×3); fixed to emit one `<p>`.
