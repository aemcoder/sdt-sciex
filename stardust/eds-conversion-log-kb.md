## 3. Chrome on this template

- **Template class.** `metadata → Template: kb-article` → `decorateTemplateAndTheme()` adds `body.kb-article`. All page-level legacy compensations hang off it (styles.css § template kb-article; header.css / footer.css appends).
- **Footer document.** `content/footer-legacy.html` = same 6-section structure as `content/footer.html` with the captured legacy values: Twitter (`https://twitter.com/SCIEXnews`, footer.js already maps host `twitter` → bird SVG), `© Copyright 2025 SCIEX`, disclaimer without the `GEN-MKT-18-7897-A` code. Page points at it via `Footer: /footer-legacy` (deployed-URL only — the harness has no pipeline for it). Must be on the publish roster.
- **Footer variant mechanism.** `footer.js` builds its root from `fragment.children` by index and never carries a fragment class, and the fragment's section divs (where a section-metadata `style` would land) are discarded. So the `legacy` variant is keyed on the fragment's distinguishing authored element: `footer .footer:has(.ftr-social a[href*="twitter.com"]) …` (v3 authors x.com). Appended rules mirror `kb-article.css § .page--kb`: `.ftr-col-desktop` padding 32px, `.ftr-links` gap 0 + `> * ~ *` margin-left 12.5px ≥640, partner `li` padding 0 / `ul` align-items flex-start, `.ftr-lang-label` margin-left 7.5px, `.ftr-disclaimer` weight 330, `.ftr-col-mobile` padding 12.5px, `.ftr-lang-mobile` hidden. A later footer.js change may add a proper `.footer.legacy` class — the CSS selector is the only thing to swap.
- **Header.** `body.kb-article header .hdr-dropbtn { font-weight: 400; padding: 0 }` (search "All" button, chrome-parity iter1).
- **Fonts.** (a) `fonts/ge2003-rg.woff2` (static Geogrotesque Regular, same-owner harvest — R-02) declared in `styles/fonts.css` as family `geogrotesque-legacy` (400 → static cut; 200/270/300/330/450/530 → the same VF file, one download); `body.kb-article { --body-font-family / --heading-font-family: geogrotesque-legacy, … }` so weight-400 chrome text on this template renders the static face as on live, and no other template changes. (b) `fonts/fontawesome-webfont.woff` (FontAwesome 4.2, SIL OFL, harvested from the live clientlib) — the star / print / chevron glyph mechanism as live; `@font-face` declared in each consuming block CSS (`article-meta`, `article-tools`, `breadcrumb`) rather than fonts.css because fonts.css loads lazily and an undeclared icon family would paint tofu first. Inline-SVG glyphs were considered and rejected: the prototype gate (0.37 %) was measured with the woff, and re-deriving four glyph outlines buys nothing.
- **No support band** on this template (live: 10px white strip) → `body.kb-article main { padding-bottom: 50px }` (40px `.home-section` + 10px `.sciex-footer` strip).

## 5. Decisions / justifications

- **Schema post-processing.** `section-schema.mjs` walks top-level `[data-section]` only; the prototype nests breadcrumb / article-tools / comment-cta inside one `data-section="kb-article"` and names the header `site-header`. `stardust/eds-schema/kb-article.json` was re-cut from that output into per-block sections in page order (`breadcrumb`, `title`, `article-meta`, `article-tools`, `article-body`, `comment-cta`; header renamed `header` so qa-gate treats it as chrome; `defaultContent: true` on the three prose sections). Items dropped on purpose: "Posted: now" (hidden comment template), the `javascript: print()` href (D15 → `#print`).
- **Print href `#print`.** D15 forbids `javascript:` URLs in content; the block intercepts the fragment link. With JS off the link is inert (page-local hash).
- **`<sup>®</sup>` authored** in h1 / prose: da.live supports sup/sub marks and the pipeline preserves them; it is captured copy, not a unit superscript the block should synthesise.
- **First breadcrumb href `/content/SCIEX/language/masters/en`** kept as captured (fidelity; it 404s on the new origin as it does off-AEM) — flagged in ready.json as a redirect-policy item for the coordinator.
- **"Rate this article"** (article-tools row 3) is the ONE authored string the live page never shows: the live stars are a text-less `span.login-link[href]`; the link is authored so the login target is content, not code, and it doubles as the star group's accessible name (visually hidden). The round-trip gate reports it as 🟡 EXTRA — intended.
- **Rating snapshot** `0 (0 votes)` — authored as displayed-hidden text, never invented (X-03 static-snapshot).
- **Bare `<br>` heights as CSS, not authored whitespace (#112).** Per-article variance (articles without the RUO note / without the trailing `&nbsp;` tail) is an accepted family-level trade: the styles model THIS byte pattern; the importer can drop `article-body` from articles lacking it.
- **Breadcrumb ownership race.** `blocks/breadcrumb` was absent at authoring time and was created here with the shared contract + the `legacy` variant. If the pharma agent's version lands over it, the `.breadcrumb.legacy` rules in `blocks/breadcrumb/breadcrumb.css` must be re-appended (they are self-contained, prefixed `/* legacy variant */`).
- **Harness note.** `build-harness.mjs` emits a bare `<body>` and the vanilla runtime (`scripts/aem.js`) no longer applies `section-metadata` client-side (pipeline-applied on rendering v2), so the local gate copy is post-processed by `stardust/.work/deploy/kb-article/harness-pipeline.mjs`: `body.kb-article` (what `Template` metadata produces), section-metadata `style` → section class with the block removed, and `<meta name="footer" content="/stardust/.work/harness/footer-legacy">` pointing at a local `.plain.html` of `content/footer-legacy.html`. This exercises the template CSS, the section styles and the legacy footer variant locally; the delivered page is still the load-bearing check for all three.
- **Schema layout for qa-gate.** `qa-gate` matches schema sections with repeats to page BLOCKS by order and excludes only `header`/`footer`; D1 default-content sections would shift that order, so `stardust/eds-schema/kb-article.json` keeps them in `defaultContentSections` (recorded, `defaultContent: true`) and `sections` holds the block-bearing sections. The article-meta `<tr>` row count is recorded under `rows` (qa-gate's tag proxies are li/article/figure/details) and asserted by the drive script instead.
- **Gate 🟡/🟠 left standing, on purpose:** lint D1 advisories on `breadcrumb` (navigation with chevrons, hidden ≤992 — structure) and `article-tools` (print / rate interactions); round-trip EXTRA "Rating:", "0 (0 votes)" (authored snapshot, hidden) and "Rate this article" (hidden accessible name).
